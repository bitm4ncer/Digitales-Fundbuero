# Upvotes („Beliebt") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Meldungen ohne Konten/Cookies upvoten können (Toggle, ein ▲ pro IP-Hash) plus Sortierung „🏆 Beliebt" — nach Spec `2026-10-09-upvotes-design.md`, Ansatz A.

**Architecture:** PostgreSQL: Tabelle `stimmen` (Unique `meldung_id`+`ip_hash`), denormalisierter Zähler `meldungen.stimmen` per Trigger, Toggle-RPC `meldung_stimme` + `meine_stimmen` (SECURITY DEFINER, IP-Hash serverseitig). Client: Feed lädt `stimmen` mit (3-stufige Fallback-Kette), Vote-Button auf der Karte (optimistisch + Rollback), Sortier-Pill „Beliebt" (`order=stimmen.desc,id.desc`), Umami-Event `stimme-abgegeben`.

**Tech Stack:** Vanilla JS (kein Build), Supabase (Postgres/PostgREST), `node --test` für Unit-Tests, lokaler Dev-Server.

**Spec:** `docs/superpowers/specs/2026-10-09-upvotes-design.md`

## Global Constraints

- Keine neuen Dependencies, kein Build-Schritt; Unit-Tests nur via `node --test tests/logic.test.js`.
- Stimmen ohne Cookies, ohne localStorage, ohne Fingerprinting; IP ausschließlich serverseitig, Hash exakt `md5('fundbuero|' || ip)` (Muster `nachricht_senden`).
- SQL idempotent (`create if not exists` / `create or replace` / `drop … if exists`); Unique `(meldung_id, ip_hash)`; Drossel 60 Aktionen/Stunde; Protokoll-Löschung 48 h.
- Default-Sortierung bleibt „Neu" (`id.desc`); „Beliebt" = `stimmen.desc,id.desc`.
- Asset-Versionen: `style.css` und `app.js` von `v=9` auf `v=10` (nur Seiten anpassen, die sie einbinden).
- Deutsch, du-Ton, Y2K-Optik; App-Code mit deutschen Kommentaren im Dateistil.
- SQL-Migrationen führt der Betreiber im Supabase-SQL-Editor aus — der Executor kann das nicht.
- Wegen parallel arbeitender Agenten: **nur die genannten Pfade** committen (`git add <pfade>`), nach jedem Commit `git status` prüfen.
- Alle Arbeiten im isolierten Worktree, Branch `feature/upvotes`.

## Review Focus

1. **Doppelklick/parallele Tabs auf „▲"** → höchstens eine Stimme, Zähler konsistent. Test: Task 4 (Button-Sperre, schneller Doppelklick = 1 Request) + Task 1 (REST-Toggle + `unique_violation`-Pfad).
2. **Netzfehler/Abbruch beim Vote** → sichtbarer Rollback, keine Phantom-Zahl. Test: Task 4 (fetch-Stub wirft Fehler, Zahl/`aria-pressed` springen zurück).
3. **Fehlende Migration/DB ohne Spalte** → Feed lädt normal, keine Vote-UI, kein Fehlerbanner. Test: Task 3 (fetch-Stub erzwingt 400, `state.stimmenAktiv === false`, `#sortBeliebt` versteckt).
4. **Reload (F5) nach Vote** → identischer Zustand/Count (Server-Wahrheit). Test: Task 4 (Reload-Check).
5. **Mobil/Tastatur-Bedienung** → Button erreichbar, `aria-pressed` wechselt, Layout läuft nicht über. Test: Task 4 (A11y-Checks) + Task 5 (schmales Viewport).
